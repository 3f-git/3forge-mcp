# AGENTS.md

Instruction file for AI coding agents working in this repo. `CLAUDE.md` (repo root) is the fuller
contributor guide; this file is the distilled, high-signal version. Both describe the same repo.

## What this repo is

Not application code — a **multi-tool AI-plugin distribution** for authoring/operating **3forge AMI**
deployments. It packages skills, agents, commands, and runtime-MCP config. It ships **no offline AMI
docs**; all AMI knowledge is fetched at runtime from a live instance via the `3forge-runtime` MCP.

## The one build rule (most important)

**Edit only the canonical source under `3forge-mcp/`. NEVER hand-edit `dist/`** — everything in
`dist/` is generated by `build/generate.mjs` and gets overwritten. `dist/` is committed (not
gitignored), so after ANY change under `3forge-mcp/` you must regenerate and commit it.

## Commands (plain ESM Node, no dependencies)

```bash
node build/generate.mjs                        # regenerate ALL dist/* targets
node build/generate.mjs copilot                # one target only (others untouched)
node build/generate.mjs --target=codex,copilot # selected targets
node build/verify.mjs                          # THE test: regen to temp, byte-diff vs dist/, validate manifests
node build/pack-portable.mjs                   # zip dist/portable -> 3forge-mcp-portable-<ver>.zip (gitignored)
claude plugin validate ./3forge-mcp            # Claude plugin (expect 0 frontmatter warnings)
claude plugin validate --strict .              # Claude marketplace (must pass --strict)
```

There is **no test runner**. `verify.mjs` is the test: it regenerates every tree into a temp dir and
byte-diffs against committed `dist/`, so any drift or hand-edit of `dist/` fails. Standard workflow:
`node build/generate.mjs && node build/verify.mjs`. Valid targets: `codex copilot opencode portable gemini cursor`.

## Architecture: one source, many targets

`build/generate.mjs` projects `3forge-mcp/` into per-tool outputs:
- **Claude Code** — consumes `3forge-mcp/` *directly*; generator only reads it. Root
  `.claude-plugin/marketplace.json` points at `./3forge-mcp`.
- **Codex / Copilot** — first-class generated plugins in `dist/codex/` / `dist/copilot/`. Generator
  rewrites Markdown per tool (e.g. `mcp__3forge-runtime__` → `mcp__3forge_runtime__`, `Agent`
  delegation → subagent workflow; agents become `.toml` / `.agent.md`).
- **Gemini / Cursor** — mirrors (instruction file + `skills/` copies). Adding one is a config-only
  change to `build/tools.json` (`writeMirror` handles it).
- **opencode** — `dist/opencode/` manual-install bundle (opencode has no plugin marketplace):
  `.opencode/{agents,commands,skills}`, an `opencode.json` (with a **disabled** `3forge_runtime` MCP
  placeholder — never a real endpoint), `AGENTS.md`, and a README. Agents become subagent Markdown
  (filename = frontmatter `name`); the generator rewrites `mcp__3forge-runtime__` → `3forge_runtime_`
  (opencode names MCP tools `<server>_<tool>`) and `ToolSearch`/`Agent` prose to opencode equivalents.
- **Portable** — `dist/portable/` manual-install bundle; kept out of the zip in `dist/` because
  non-deterministic zip mtimes would break the `verify.mjs` byte-diff.

New **first-class** target = add `build/<tool>/` templates + a `write<Tool>Plugin` fn in
`generate.mjs` (copy `writeCodexPlugin` / `writeCopilotPlugin`). New **mirror** = `build/tools.json` entry.

## Two files that must stay in sync

The operating guidance is duplicated by necessity — edit BOTH together:
- `3forge-mcp/CLAUDE.md` — canonical source projected into every mirror's instruction file.
- `3forge-mcp/skills/using-3forge-runtime/SKILL.md` — same guidance as a skill (Claude plugins do
  NOT load a plugin-root `CLAUDE.md` as context).

Note: repo-root `CLAUDE.md`/`AGENTS.md` (contributor guidance) ≠ `3forge-mcp/CLAUDE.md` (projected
plugin operating guidance). Don't conflate them.

## Authoring conventions

- **Skills:** `3forge-mcp/skills/<name>/SKILL.md`; `name:` MUST equal the directory name and
  `description:` MUST be a "Use when…" trigger or the skill isn't discoverable.
- **Tool names are NOT static** — the live `3forge-runtime` server is the authoritative catalog and
  the plugin ships no snapshot. Confirm any hardcoded tool name against a live server.
- Only reference agents/skills that exist in this package.

## Release

Bump `version` in `3forge-mcp/.claude-plugin/plugin.json` (generator stamps it into Codex/Copilot
manifests), then `node build/generate.mjs && node build/verify.mjs`, commit, `git tag vX.Y.Z && git
push origin main --tags`. Never commit secrets, internal hostnames, or env-specific MCP endpoint config.
